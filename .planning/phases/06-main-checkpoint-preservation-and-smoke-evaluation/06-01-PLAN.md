# Plan 06-01: Main Checkpoint Preservation And Smoke Evaluation

**Phase:** 6 - Main Checkpoint Preservation And Smoke Evaluation
**Status:** Accepted

## Goal

Preserve the current main-condition checkpoint and verify that it can run
through the evaluation/player path without starting new training.

## Tasks

1. On `server1-jinsu`, confirm no active PHC-Pain job is still running and
   record current Slurm occupancy for `idx0..idx3`.
2. Create a timestamped backup of
   `output/HumanoidIm/phc_shape_pnn_iccv_pain_v1/Humanoid.pth`, for example
   `Humanoid_short50_20260427_2314.pth`.
3. Copy the relevant smoke/short50 Slurm logs into a stable evidence folder or
   record their exact paths in the phase summary.
4. Run a no-training `test=True` evaluation smoke with `env.num_envs=1`,
   `headless=True`, `learning.params.config.player.games_num=1`, and the same
   v1 env/checkpoint.
5. Verify the evaluation log shows player restore/adaptation and no shape
   mismatch.
6. Write `06-SUMMARY.md` with checkpoint paths, log paths, exact command,
   Slurm job id, and a verdict: `MAIN_CHECKPOINT_USABLE`, `BLOCKED`, or
   `NEEDS_RERUN`.

## Verification

- `ls -lh` shows the original `Humanoid.pth` and timestamped backup.
- `squeue` shows the eval job is not colliding with occupied GPU indices.
- Eval log contains `Device count 1` and no traceback.
- Eval log confirms observation/player restore compatibility; if explicit
  adaptation text is absent, verify no `mat1 and mat2 shapes cannot be
  multiplied` or running-mean shape error occurs.
- `git diff --check`

## Non-Goals

- Do not launch additional training.
- Do not run ablations.
- Do not claim pain/load mechanism success from smoke alone.
