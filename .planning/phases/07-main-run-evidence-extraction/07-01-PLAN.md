# Plan 07-01: Main Run Evidence Extraction

**Phase:** 7 - Main Run Evidence Extraction
**Status:** Accepted

## Goal

Turn the current main-condition run into a documented evidence package with a
clear verdict on whether it is sufficient for comparison or blocked by missing
metrics.

## Tasks

1. Copy or reference the Phase 6-preserved main logs and checkpoint backup.
2. Extract reward, frame count, FPS, and episode length trajectory from the
   `3968` stdout log into a small summary table.
3. Search logs and output artifacts for required pain keys:
   `pain_v1_right_knee_load`, `pain_v1_right_knee_drive`,
   `pain_v1_right_knee_state`, and `pain_v1_reward_cost_mean`.
4. If pain keys exist, compute main-run aggregate metrics required by
   `docs/superpowers/phc_pain_v1_evaluation_protocol.md`.
5. If pain keys do not exist, document the gap and define the minimal logging
   instrumentation needed before Phase 8 can produce mechanism evidence.
6. Create a main-run JSON summary under the phase directory and update
   `docs/superpowers/phc_pain_v1_evidence_template.md` or a copied evidence
   artifact with the main condition metadata.
7. Write `07-SUMMARY.md` with verdict:
   `MAIN_EVIDENCE_READY_FOR_ABLATION`, `METRICS_BLOCKED`, or
   `RUN_INVALID`.

## Verification

- Summary file includes exact checkpoint, log paths, command, GPU index, and
  commit.
- Reward/episode-length extraction is reproducible from the log text.
- Pain metric availability is explicitly PASS/BLOCKED, not inferred.
- If aggregate JSON is produced, `python3 scripts/phc_pain_v1_evaluate.py`
  returns the expected `BLOCKED` until ablation conditions exist.
- `git diff --check`

## Non-Goals

- Do not run new training.
- Do not compare against ablations.
- Do not claim clinical or patient-specific validity.
