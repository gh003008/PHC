# Phase 07.1 Context: Pain Metric Scalar Logging Instrumentation

**Inserted:** 2026-04-28
**Reason:** Phase 7 found that the main PHC-Pain-v1 run had reward and episode
length evidence, but no TensorBoard scalar tags containing `pain`.

## Problem

`HumanoidImPainV1` already exposes required pain metrics through env `extras`,
including:

- `pain_v1_right_knee_load`
- `pain_v1_right_knee_drive`
- `pain_v1_right_knee_state`
- `pain_v1_reward_cost_mean`

The training logs did not contain those keys because the AMP training loop only
promoted selected reward/training tensors into `train_info`; arbitrary numeric
env `infos` were processed by observers but not recorded as scalar summaries.

## Goal

Promote numeric `pain_v1_*` entries from env `infos` into train-time scalar
logging so a short GPU probe can confirm the tags before Phase 8 ablations.

## Scope

- Collect numeric scalar `pain_v1_*` values during AMP rollout.
- Average each key over the rollout horizon.
- Add the averaged values to `train_info`.
- Let the existing TensorBoard/W&B logging path write the exact scalar tags.

## Non-Goals

- Do not change the pain mechanism.
- Do not run Phase 8 ablations.
- Do not reinterpret the existing short50 run as mechanism evidence.
- Do not add patient-specific or clinical claims.
