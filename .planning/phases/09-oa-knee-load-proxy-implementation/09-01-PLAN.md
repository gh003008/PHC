# Phase 9 Plan: OA Knee Load Proxy Implementation

## Goal

Replace the torque-centric `HumanoidImPainV1` knee pain drive with an OA-style knee joint loading proxy using contact/compression and KAM/KFM moment-arm estimates, without launching training.

## Source Plan

Detailed task scaffold:

`docs/superpowers/plans/2026-04-29-phc-pain-v15-knee-load-proxy.md`

## Requirements Covered

- OA-01: Preserve `pain_body_state` as reward-facing variable.
- OA-02: Add pure-torch OA knee load helpers.
- OA-03: Preserve legacy torque proxy diagnostics.
- OA-04: Add `torque_v13`, `oa_contact_v14`, and `oa_contact_v15` proxy modes.
- OA-05: Verify finite `pain_v1_*` probe metrics before training.
- OA-06: Default env config to `oa_contact_v15`.
- OA-07: Update evaluation metric hierarchy.
- OA-08: Keep proxy validity boundary explicit.

## Execution Tasks

1. Add unit tests and pure-torch helpers in `phc/env/util/pain_baseline.py`.
2. Wire OA load proxy modes into `phc/env/tasks/humanoid_im_pain.py`.
3. Update `phc/data/cfg/env/env_im_pain_v1.yaml` defaults.
4. Update `docs/superpowers/phc_pain_v1_evaluation_protocol.md`.
5. Run unit, syntax, YAML, and local headless probe checks.
6. Write Phase 9 summary and verification artifacts.
